# Tourism JWT Project

Spring Boot REST API that retrieves all tourist records only after validating an existing JWT.

## Requirements
- Java 21
- Maven (or the Maven wrapper generated by your IDE)
- MySQL 8+
- A pre-generated JWT and the matching signing secret

## Import into Spring Tool Suite / Eclipse
1. Extract `tourism-jwt-project.zip`.
2. Open Spring Tool Suite.
3. Select **File → Import → Maven → Existing Maven Projects**.
4. Browse to the extracted `tourism-jwt-project` folder.
5. Select `pom.xml`, then click **Finish**.
6. Wait for Maven dependencies to download.

## Database setup
Create the database (or let the configured URL create it):

```sql
CREATE DATABASE tourismdb;
```

Open `src/main/resources/application.properties` and set:
- `spring.datasource.username`
- `spring.datasource.password`
- `app.jwt.secret`

The `app.jwt.secret` value must be exactly the same key used to sign the pre-generated JWT. Do not commit real secrets to Git.

The application creates the `tourists` table automatically. Optional sample records:

```sql
USE tourismdb;

INSERT INTO tourists (name, email, country, phone) VALUES
('Rahul', 'rahul@example.com', 'India', '9876543210'),
('Priya', 'priya@example.com', 'USA', '9876543211');
```

## Run
Run `TourismApplication.java` as **Spring Boot App**.

## API
- Method: `GET`
- URL: `http://localhost:8080/api/tourists/all`
- Swagger UI: `http://localhost:8080/swagger-ui/index.html`

In Swagger UI:
1. Click **Authorize**.
2. Paste the pre-generated JWT only (do not type `Bearer ` when the Swagger bearer dialog is used).
3. Click **Authorize**, close the dialog.
4. Expand `GET /api/tourists/all`, click **Try it out**, then **Execute**.

## Expected responses
- `200 OK`: token signature and expiry are valid; returns the tourist list.
- `401 Unauthorized`: token is missing, malformed, invalid, expired, or signed with a different secret.

## Important
This project validates the JWT signature and expiry. It does not generate tokens. It assumes an HS256-signed JWT; if your existing token uses a different algorithm or key format, adjust `JwtUtil` to match the existing issuer. For a production dashboard, return a restricted response DTO rather than exposing every entity field, and enforce authorization roles/scopes as well as token validity.
